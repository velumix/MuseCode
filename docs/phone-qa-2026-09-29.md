automation used the phone's authorized wireless-debugging connection. The

## Physical phone results

- Pairing required desktop approval; live history appeared on the phone.
- Real touch input opened the Android keyboard. Portrait, landscape, and 130%
  system text layouts were inspected without horizontal page overflow.
  Final production assets provided 131 CSS pixels of transcript in the
  411 × 447 portrait keyboard viewport, up from 34, with Send fully visible.
- Context details, diagnostics, Memory, Kanban and Bots were opened on device.
  The reasoning selector changed the native session successfully.
- Three real Codex turns ran in Standard mode. Fresh output was 11 tokens in
  4,692 ms; the next resumed turn reported 8 tokens in 4,459 ms, not the lifetime
  total. The second context snapshot was 20,897 / 258,400 tokens.
- A test note saved from the phone was recalled by real Codex. The memory event
  named the test note and reported 564 injected bytes; the answer matched its
  QA-only value. This verifies Velum's local note retrieval, not external memory
  services or UI/document attachments.
- After the persistence fix, an actual `am force-stop` and relaunch retained the
  committed draft, pairing, reasoning choice and usage history.
- Terminating the isolated desktop process showed the offline state, disabled
  Send and retained the draft. Restarting the companion restored access.
- The real native Codex workspace probe passed directory listing, known-file
  reading, creation, editing, read-back and cleanup in Standard mode. Active
  metadata reported `workspace-write`, restricted filesystem/network and
  approval policy `never`. Host and agent results were separately recorded;
  no probe directories remained.

The earlier investigation also verified Standard → YOLO → Standard transitions;
see [workspace-access-fix.md](workspace-access-fix.md). Its root cause was host
success being described as agent success, combined with the Windows sandbox's
different identity/folder boundaries and provider command policy. There was no
general NTFS denial on the actual project repository.

## Limits

Tailscale was not installed on this phone; private wireless application routing
and QR camera scanning were not verified on hardware. Functional inspection used
the debug APK to protect the existing release app's private pairing and drafts;
release APK installation and native launch were checked separately. Other phones,
Android versions, and real Muse/Antigravity token counters were not verified.
No agent UI/document attachment discovery was added or claimed.

The phone interface is served by the desktop companion. Installing only the APK
does not update that interface; the new desktop build must also be used.
