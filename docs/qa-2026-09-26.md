# Muse Code QA and improvement pass — 2026-09-26

Reviewed the current working tree of the Tauri/React desktop app, including the existing
uncommitted rich chat work. The original changes were preserved. Fixes remain local and
uncommitted; account configuration and provider credentials were not changed. The initial QA
pass preserved the installed app; the later desktop-icon request authorized the update below.

## Findings fixed

| Area | Reproduced or identified problem | Result |
| --- | --- | --- |
| Mode switching | Clicking the selected mode restarted the session; Agent → Terminal → Agent erased messages, draft, workspace, and YOLO state. | Mode switches preserve both mounted views and their independent statuses; terminal loads on demand. |
| Workspace validation | An invalid directory destroyed the current transcript and disabled Apply. | Validate before replacing the session, retain the conversation on error, allow correction/retry. |
| Workspace keyboard path | Enter in the directory field bypassed the button's running-state guard and interrupted work. | Both submission paths share the guard. |
| Startup/teardown | Delayed event registration or session creation could finish after cleanup, leaking listeners/processes, including React StrictMode. | Await initialization during cleanup, unsubscribe late listeners, use a fresh native identity for each generation. |
| Turn completion | UI could show completion while the old child still occupied the session, rejecting a quick follow-up. Old readers looked up replacement sessions by tab ID. | Reader owns its original session; completion is emitted after cleanup and clearing the running flag. |
| Process cleanup | Native window exit had no explicit agent/PTY cleanup; terminal shim descendants could survive a direct child kill. | Stop and tab close terminate owned process trees. Window Close now hides to the tray; explicit Quit cleans up both modes. |
| Windows launch paths | Chat launch failed when the CLI path contained spaces and `&`; terminal used the same fragile wrapping approach. | Correct headless batch handling and a ConPTY wrapper that passes the executable path as data. Native tests exercise these paths. |
| Terminal workspace | Terminal always started in the home directory even when the tab selected a project. | Terminal starts/restarts in the validated tab workspace. |
| Final answers | `turn_end.text` was ignored when no streaming deltas arrived. | Display final-only answers without duplicating streamed responses. |
| Failure visibility | Failed turns without a reason silently returned to Ready. Failed sends erased the prompt. | Show explicit failure state and restore rejected prompts for retry. |
| Stop display | Tool cards could remain running after their turn stopped. | Finish outstanding tool cards and show a stopped notice. |
| Input handling | IME composition Enter could submit a message; rapid sends had a stale running guard. | Respect composition and update the running guard synchronously. |
| Clipboard | Message Copy overlaid the code block Copy button, intercepting clicks. | Separate copy controls in layout; distinguish their accessible names; restore focus after fallback copying. |
| Keyboard/accessibility | Session tabs lacked keyboard selection; invalid nested controls and tab-list children; palette allowed focus to escape. | Arrow/Home/End/Delete tab controls, valid tab semantics, palette focus containment/return, named composer and command list. |
| PTY output | Invalid UTF-8 bytes delayed valid trailing output until another read or EOF. | Drain every complete segment immediately while retaining only incomplete sequences. |
| Prompt staging | Prompt files were retained until tab destruction. | Per-turn ownership removes files after turns, Stop, failed spawn, and application exit. |
| Frontend loading | Terminal code loaded even when using only chat. | Lazy terminal bundle; initial JS reduced from about 785 kB to 420 kB before compression. |

## Recommended next work, in order

1. **Save and resume sessions.** Tabs, transcripts, drafts, workspace choices, and the binding to
   a CLI session survive closing to the tray, but disappear after explicit Quit or a crash. Add durable session records,
   transcript replay, and recovery for interrupted turns. This also makes accidental tab close
   or Restart recoverable. Existing CLI logs are retained but the app cannot reopen them.
2. **Implement interactive questions and approvals in chat.** Current `exec` runs display notices;
   `--user-input-auto-resolve` auto-cancels questions. A supported bidirectional control transport
   and request/response state are needed. The existing design discusses `serve`, but a real
   tool-calling integration test must prove the transport before adding approval buttons.
   YOLO does not solve question input or synchronize a terminal conversation.
3. **Make project selection clearer.** Add a native folder picker, recent projects, project-based
   tab names, and visible workspace context. Applying a new workspace intentionally starts fresh;
   Agent and Terminal are separate conversations within that workspace.
4. **Expose startup/configuration diagnostics.** Detect a missing/incompatible CLI before the
   first send, display the effective provider/model and CLI version, and offer actionable
   authentication/configuration errors without exposing secrets.
5. **Benchmark long sessions and finish output ergonomics.** Transcript blocks are retained in
   memory and updated during streaming. Measure long histories and high-volume tool output;
   then add batching/virtualization if needed. Expanded tool output is intentionally capped;
   provide an explicit full-output/export action. Local file links are currently inert.
6. **Expand release validation.** The current installation/upgrade, shortcut, and packaged
   WebView2 checks pass. Add a disposable clean-install/uninstall cycle and CI for the repeatable
   checks, then run a small controlled live-provider test covering a read-only tool and approval.

## Tray and Windows notifications follow-up

Window Close and Alt+F4 now hide the main window while Rust Agent readers, ConPTY sessions,
and the mounted React views continue running. The tray uses the Muse logo and offers Open,
a notification toggle, a test notification, and Quit. A single-instance plugin restores the
same window when the desktop shortcut is launched again. Explicit Quit still terminates
owned process trees; it also removes notifications tied to the ended in-memory conversations.

Background Agent completion/failure events are delivered by Rust using Windows ToastGeneric
notifications. Foreground, cancelled, muted, and quitting turns are suppressed. Notification
text is generic; prompts, answers, errors, and paths remain inside Muse. Stable tags replace
older results from the same tab. The footer and tray share a saved per-user notification
preference; delivery errors are shown in the UI. Interactive Terminal tasks are preserved in
the tray but do not expose structured completion events for these notifications.

Installed testing caught and fixed Windows returning `ERROR_NOT_FOUND` when reading settings
before an unpackaged app sends its first notification. That specific first-use case now allows
Windows to process the initial notification; known disabled settings and other errors remain
reported. A Rust regression test covers this without overriding Windows notification policy.

The NSIS installer registers the application identity, branded icon, and native COM activator
in the user's Windows registry. The activator restores the window and selects the originating
Agent conversation, including when the action comes from Notification Center after a popup
has timed out. This follows Microsoft's [desktop toast activation documentation](https://learn.microsoft.com/en-us/windows/apps/design/shell/tiles-and-notifications/send-local-toast-desktop-cpp-wrl).
The app uses Tauri's [tray API](https://v2.tauri.app/learn/system-tray/) and
[single-instance plugin](https://v2.tauri.app/plugin/single-instance/) for window lifetime.
